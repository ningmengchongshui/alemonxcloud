# 首发阻断项收口计划

目标：将 AlemonX Cloud 从“可联调”提升到可灰度收费的单节点首发 MVP。本文只覆盖当前审计中编号 1、2、3、4、5、7 的阻断项；端到端演练和集成测试作为发布门禁另行执行。

## 执行顺序

```text
生产依赖强制失败 ─┬─> 真实镜像摘要部署 ─> 订单与节点可用性校验
                  └─> RabbitMQ 自动恢复 ─> 管理台配置编辑 ─> 指标与告警接入
```

前四项先于任何收费流量上线；管理台和可观测性可以并行开发，但必须在灰度前完成。

## 1. 生产依赖强制失败

### 改动

- 将会话、实例、控制面初始化函数改为返回错误，不再在 `GIN_MODE=release` 下回退内存存储。
- Redis、MySQL、RabbitMQ、Agent 任一连接或初始化失败时，进程拒绝提供 HTTP 服务并以非零状态退出。
- 开发模式保留内存实现，但 API 响应显式标注开发状态，且禁用真实订单确认与 Agent 操作。
- `/healthz` 增加 `ready` 状态：只有 MySQL、Redis、RabbitMQ、Agent 均可用时返回 200；存活探针与就绪探针分离。

### 验收

- 分别断开 MySQL、Redis、RabbitMQ、Agent 后，以 release 模式启动，进程在启动阶段失败。
- 运行中依赖失联时就绪检查返回非 200，恢复后自动回到 ready。
- 重启应用后，订单、实例、任务与登录会话仍从外部存储恢复。

## 2. 不可变镜像摘要部署

### 改动

- 镜像版本创建 API 仅接受格式正确的 `sha256:<64位十六进制>` 摘要；禁止使用演示摘要。
- 镜像版本表把 `image_ref` 与 `image_digest` 组合为唯一的实际部署引用：`image_ref@image_digest`。
- Agent 创建容器仅接受含 `@sha256:` 的镜像引用；拒绝 tag-only 镜像。
- 迁移既有默认商品：管理员必须填写真实仓库摘要后才可启用销售。
- 创建订单与确认订单均再次检查镜像版本启用状态和摘要合法性。

### 验收

- 任意 tag-only、摘要格式错误或后台未启用的镜像均无法进入任务。
- Docker inspect 的 `RepoDigests` 与后台记录摘要一致。
- 上游同名 tag 被覆盖后，已审核版本仍拉取同一摘要镜像。

## 3. RabbitMQ 自动恢复与可靠投递

### 改动

- 引入单独的队列连接管理器：监听 `NotifyClose`，指数退避重连，重建 exchange、queue、binding 与 consumer。
- 发布任务采用 publisher confirm；确认收款事务提交后的未确认任务维持 `pending`，由恢复扫描器重新发布。
- 任务消费者设置合理 prefetch；消费失败时更新数据库任务状态后再确认或拒绝消息。
- 任务状态增加 `queued`、`running`、`retrying`、`failed`、`succeeded` 的可追踪转换，并记录最后一次错误和下次执行时间。
- 死信队列保留管理员可检索的失败消息；人工重试生成新的投递记录但沿用幂等键。

### 验收

- RabbitMQ 在创建任务后重启，任务不丢失且恢复后仅执行一次。
- 应用在 RabbitMQ 运行中重启后，自动恢复消费，不需要人工重启第二次。
- 人为让 Agent 连续失败三次，任务进入失败状态和死信队列；管理员重试后可成功完成。

## 4. 节点可用性纳入分配

### 改动

- 节点增加最近心跳阈值，例如 90 秒；节点状态划分为 `online`、`offline`、`disabled`。
- Agent 状态接口返回 Docker 可用性、版本、磁盘剩余空间和受管容器数量；全部接口继续由 Bearer Token 保护。
- 订单确认事务只选择启用且心跳未过期的节点；无节点可用时返回“裸机节点暂不可用”，不创建预占和任务。
- 容器状态同步写入实例健康状态；连续异常记录审计日志并计入告警指标。

### 验收

- 停止 Agent 或阻断其网络 90 秒后，节点显示离线，管理员不能确认新订单。
- Agent 恢复、心跳刷新后，节点自动恢复可分配状态。
- 实例健康检查失败可在管理台定位到实例、节点与最近错误。

## 5. 完整超级管理台配置编辑

### 改动

- 镜像页：新增版本、展示不可变摘要、启用/下架；已有版本不可编辑摘要。
- 套餐页：新增、编辑 CPU/内存/月价（分）、排序、启用状态；存在活跃订单时的修改须仅影响后续订单。
- 节点页：编辑总 CPU、内存、Agent 内网地址、启用状态；展示已预占和可用资源、心跳与健康。
- 所有写操作增加二次确认、请求中禁用、成功/失败反馈及审计日志。
- Redux Toolkit Query 统一管理服务端数据；持久化仅保留页面偏好，不保存会话和业务响应。

### 验收

- 管理员完成商品/套餐/节点配置后，用户台立即只显示启用商品。
- 下架镜像或套餐后，旧订单可追踪但新订单不能选择。
- 非 `cloud:admin` 用户访问管理 API 与页面均被拒绝。

## 7. 指标、监控与告警

### 改动

- 提供受网络访问控制的 Prometheus `/metrics`，输出 HTTP、订单状态、任务积压/失败、Agent 心跳、节点资源、实例健康、磁盘空间等指标。
- 保留 `/healthz` 作为存活检查，新增 `/readyz` 作为依赖就绪检查。
- 日志统一 JSON 结构，包含 requestId、actorId、orderId、instanceId、taskId；绝不记录令牌、Cookie、密码或完整支付内容。
- 在部署包提供 Prometheus 抓取示例与 Alertmanager 规则模板，不在应用代码中硬编码通知渠道。
- 最低告警规则：依赖不可用、Agent 心跳超时、磁盘低于 15%、任务积压超过 10 分钟、失败任务出现、实例健康失败。

### 验收

- 人为制造每一种故障，指标在一个抓取周期内变化，告警在规则窗口内触发。
- 恢复依赖和 Agent 后，就绪状态、指标与告警自动恢复。

## 发布门禁

- 所有上述验收项完成并留存演练记录。
- 至少以真实外部 MySQL、Redis、RabbitMQ、systemd Agent 和泛域名 Nginx 完成一次全流程：下单 → 人工确认 → 部署 → 域名访问 → 续费 → 到期停止 → 保留期清理。
- 不允许 `.env`、数据库密码、Agent 令牌、OAuth Cookie 或构建产物进入 Git。
