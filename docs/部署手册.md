# 部署手册

## 前置条件

- Linux 裸机，已安装 Docker Engine、Docker Compose、Nginx 与 systemd。
- 已准备 `xcloud.alemonjs.com` 和 `*.alemonjs.com` 的 DNS 记录及 TLS 证书。
- Auth 已创建公共 PKCE 客户端，回调地址为 `https://xcloud.alemonjs.com/callback`。
- 服务器具备 MySQL、Redis、RabbitMQ 的持久化磁盘空间与备份策略。

## 配置服务端

复制 `.env.example` 为 `.env`，在生产环境至少设置：

```dotenv
GIN_MODE=release
PUBLIC_URL=https://xcloud.alemonjs.com
AUTH_OIDC_CLIENT_ID=应用客户端ID
AUTH_OIDC_REDIRECT_URL=https://xcloud.alemonjs.com/callback
MYSQL_DSN=xcloud:密码@tcp(mysql:3306)/xcloud?charset=utf8mb4&parseTime=true&loc=Local
SESSION_REDIS_URL=redis://redis:6379/0
RABBITMQ_URL=amqp://xcloud:密码@rabbitmq:5672/
XCLOUD_AGENT_URL=http://host.docker.internal:13092
XCLOUD_AGENT_TOKEN=高强度随机令牌
XCLOUD_INSTANCE_DOMAIN=alemonjs.com
XCLOUD_INSTANCE_DATA_ROOT=/var/lib/xcloud/instances
```

`host.docker.internal` 已由 Compose 映射到宿主机网关；若服务端不运行在容器内，改用 `http://127.0.0.1:13092`。生产模式缺少任一关键配置会停止启动。

MySQL、Redis 和 RabbitMQ 是外部独立服务，Compose 不会创建它们。根目录的 Compose 只构建并运行 `alemonxcloud` 主应用；`xcloud-agent` 必须按后文作为宿主机 systemd 服务单独安装。确认 `.env` 中的地址可从主应用容器访问后，启动服务端：

```bash
docker compose up -d --build
docker compose ps
curl http://127.0.0.1:13082/healthz
```

## 安装裸机 agent

agent 是宿主机 systemd 服务，不是 Docker 容器。创建用户容器网络与数据目录：

```bash
docker network create xcloud_network
install -d -m 0750 /var/lib/xcloud/instances
```

构建二进制后，先创建 `/etc/xcloud-agent.env`，至少包含：

```dotenv
GIN_MODE=release
AGENT_ADDR=0.0.0.0:13092
XCLOUD_AGENT_TOKEN=与服务端完全一致的令牌
XCLOUD_DOCKER_NETWORK=xcloud_network
XCLOUD_INSTANCE_DATA_ROOT=/var/lib/xcloud/instances
```

首次以 root 运行二进制会自动复制自身、注册 systemd service 并启动：

```bash
make agent-build
sudo agent/xcloud-agent
systemctl status xcloud-agent
```

Agent 需要监听 Docker 网桥，防火墙必须只放行 Compose 固定控制网段
`172.30.0.0/24` 到 13092，不能放行公网。使用 firewalld 的服务器可执行：

```bash
sudo firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="172.30.0.0/24" port port="13092" protocol="tcp" accept'
sudo firewall-cmd --permanent --add-rich-rule='rule family="ipv4" port port="13092" protocol="tcp" drop'
sudo firewall-cmd --reload
```

若已有更高优先级的允许规则（例如直接开放 13092 或开放全部端口），必须先移除；令牌验证是第二道防线，不能替代防火墙。更新 Compose 网络后，需重新创建应用容器：`docker compose down && docker compose up -d --build`。

## Nginx、DNS 与 TLS

- 使用 `deploy/nginx-xcloud-server.conf` 代理主站到 `127.0.0.1:13082`。
- 使用 `deploy/nginx-instance-proxy.conf` 代理泛域名实例请求到 `127.0.0.1:13092`。
- 两个 server 块都必须配置有效的 `listen 443 ssl`、证书路径和 80 到 443 的跳转；仓库示例不携带证书路径。
- agent 端口 13092 监听所有地址，但防火墙只允许本机与 `172.30.0.0/24` 的控制平面容器访问；禁止安全组和防火墙对公网放行。

## 发布后核对

1. 主站 Auth 登录和回调成功。
2. `systemctl status xcloud-agent` 正常，`curl http://127.0.0.1:13092/healthz` 返回成功。
3. MySQL、Redis、RabbitMQ 均有健康状态。
4. 泛域名证书覆盖随机实例域名。
5. 确认容器没有 `0.0.0.0:宿主机端口->17390` 映射。

订单与队列执行器尚未实现时，不可将当前版本用于付费交付。
