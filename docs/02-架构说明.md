# 架构说明

## 运行单元

```text
浏览器 ──HTTPS──> Nginx ──> xCloud 控制面
                               ├─ MySQL：业务、任务、订单、节点、审计
                               ├─ Redis：会话、Gateway Owner 目录
                               ├─ RabbitMQ：平台节点异步任务
                               ├─ xcloud-agent：平台裸机 Docker 执行面
                               └─ Tunnel Gateway A/B：自建节点数据平面
                                                          └─ xcloud-control：用户服务器 Docker 执行面
```

控制面只负责认证、权限、商品/钱包/订单、调度、实例状态机、任务、审计和 API。它不直接访问 Docker Socket。

## 两类节点

| 类型 | 执行进程 | 任务通道 | 实例访问 |
| --- | --- | --- | --- |
| 平台裸机节点 | `xcloud-agent` systemd | RabbitMQ → Agent 内网 HTTP | Nginx → 控制面 → Agent → 容器 |
| 用户自建节点 | `xcloud-control` systemd | 控制面 → 私有 Gateway → WSS 隧道 | Nginx → 控制面 → 私有 Gateway → WSS 隧道 → 容器 |

两类节点都只运行平台审核镜像，实例使用受管 Compose、独立数据目录、`/app/workspace` 工作区、资源限制和随机路由键。用户容器不映射宿主机端口。

## 自建节点的三个入口

```text
xcloud-control ──WSS──> tunnel.alemonjs.com/connect ──> Gateway A 或 B
控制面 ──HTTPS + Bearer──> tunnel-internal.alemonjs.com/{command,terminal,proxy}
用户 ──HTTPS──> xcloud-r<路由键>.alemonjs.com ──> 控制面实例路由
```

Gateway 以 Redis 保存“设备 → Owner Gateway”短时目录。请求落到非 Owner 时，Gateway 之间通过 mTLS 内网转发；控制面重启不会断开已建立的设备隧道。详细变量边界见 [配置参考](00-配置参考.md)。

## 主流程

1. 用户通过 Auth OIDC 登录，控制面保存 HttpOnly 会话。
2. 平台实例购买在同一事务中校验钱包余额、镜像版本、套餐和节点资源，然后创建订单、资源预占和任务。
3. 平台任务经 RabbitMQ 到达裸机 Agent；自建节点任务经 Gateway 隧道到达自建 Agent。
4. Agent 只操作带 `xcloud.managed=true` 标签、匹配实例路由键、位于受管数据根目录的 Compose 项目。
5. 域名访问始终先经过控制面路由；控制面再根据节点类型转给平台 Agent 或 Gateway。

## 生命周期

实例状态与运行状态分离：业务状态记录 `running`、`destroy_scheduled`、`destroyed`、`purged`；运行状态记录容器实际 `running`、`stopped` 或 `missing`。

- 退款：服务持续至退款后的最终到期时间，再销毁容器，数据保留 30 天。
- 正常到期或手动销毁：先进入 7 天待销毁期，期间服务保持原运行状态；随后销毁容器，数据再保留 30 天。
- `destroyed` 后用户可归档隐藏记录；`purged` 后数据已物理删除，但订单、任务和审计仍可查询。
