# 架构与状态

## 运行拓扑

```text
浏览器 ─HTTPS→ Nginx ─HTTP→ xcloud-server (:8082)
                              ├─ Auth：OIDC Authorization Code + PKCE
                              ├─ MySQL：实例与 MVP 业务表
                              ├─ Redis：服务端会话
                              ├─ RabbitMQ：部署任务队列
                              └─ HTTP + Bearer Token → xcloud-agent (host gateway:13092)
                                                           └─ Docker xcloud_network → AlemonX (:17390)
```

用户实例不发布宿主机端口。访问 `xcloud-r<16位十六进制哈希>.alemonjs.com` 时，Nginx 将路由键传给 agent；agent 以 Docker 标签 `xcloud.route` 查找容器，通过 `docker inspect` 取得内部 IP 后反代到 17390。

## 已实现

- Auth 公共客户端的 PKCE 登录、HttpOnly 服务端会话与管理员权限判断。
- React 用户台原型、开发模式内置超级管理员、实例创建/启动/停止/删除 API。
- agent 的令牌校验、Docker 资源限制、数据卷、健康检查、内部网络与反向代理。
- MySQL 正式迁移：实例、平台设置、节点、不可变镜像版本、套餐、订单、任务和审计日志；首次启动会创建默认 16 核 / 256 GB 节点及基础 AlemonX 商品目录。
- 用户只可按后台配置的镜像版本和套餐创建待支付订单；管理员确认收款时在串行化事务内锁定节点、重新核验容量、预占资源、创建实例记录和部署任务。未付款订单不占资源。
- 超级管理 API：镜像版本、套餐、节点配额、订单确认/拒绝、任务重试、资源与任务指标。前端包含订单中心和超级管理台。
- RabbitMQ 持久化部署队列、失败死信队列和数据库任务状态；消费者实际调用 Agent，最多三次有限重试。服务或 RabbitMQ 重启后会从数据库重新投递待执行任务。
- Agent 令牌保护的 Docker/容器状态接口；控制面每分钟写入节点心跳并同步容器运行状态。
- 到期任务会停止实例并保留数据 7 天；删除操作同样先停止、进入保留期，清理任务到期后才删除容器和数据目录。
- Redis 会话存储、基础健康检查和生产配置缺失时拒绝启动。

## 首发前仍需运维配置

- 在生产 MySQL 上执行一次应用启动，让自动迁移创建新增列和默认商品；随后由管理员按实际镜像摘要、套餐价格和裸机总配额调整目录。
- 配置 RabbitMQ 的持久化磁盘与监控；将 `/healthz`、MySQL、Redis、RabbitMQ、Agent、任务积压、磁盘空间接入已有告警系统。应用已提供基础指标 API，但不内置告警发送器。
- 上线前完成一次全流程演练：下单、确认收款、实例域名访问、到期停止、7 天清理与任务重试。

控制面 MVP 已具备完整业务闭环；付款仍是人工核验，自动在线支付、退款、多节点调度和实时日志流仍不在首发范围。
