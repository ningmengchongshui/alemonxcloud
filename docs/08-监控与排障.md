# 监控与排障

## 检查顺序

```bash
docker compose ps
curl http://127.0.0.1:13082/healthz
curl http://127.0.0.1:13082/readyz
systemctl status xcloud-agent
curl http://127.0.0.1:13092/healthz
```

## 指标与告警

`/metrics` 需要 `Authorization: Bearer $XCLOUD_METRICS_TOKEN`，只允许监控网段访问。可导入 `deploy/prometheus-alerts.yml`。重点关注依赖不可用、Agent 心跳超时、任务积压/失败、实例健康失败和磁盘剩余空间低于 15%。

| 现象 | 优先检查 |
|---|---|
| `/readyz` 失败 | `.env` 连接串、依赖网络、Agent 地址和令牌 |
| Agent 超时 | 防火墙、`172.30.0.0/24`、systemd 状态、13092 监听 |
| 域名打不开 | DNS、泛域名证书、Nginx 配置、路由键格式 |
| 任务失败 | 任务错误、RabbitMQ、镜像摘要和 Agent 日志 |
| 节点不能接单 | 90 秒心跳、节点是否 disabled、可用配额 |
| 运行资源丢失 | 管理台“运行资源丢失”、节点容器与实例数据目录；不得直接重建 |
| 销毁受阻 / 离线影响实例 | 节点管理中的最后心跳、待清理任务和 Agent 错误；恢复节点后等待补偿投递 |

## 实例生命周期处理

- 部署任务连续失败三次后，实例会显示为“需要处理”。用户可从实例页发起“重试部署”；系统会先清除残留容器运行资源，但不会删除数据目录或重新扣款。
- `runtime_status=missing` 表示 Agent 明确报告容器不存在。平台会阻断访问而不自动重建或删除数据；管理员应先核对节点、容器与实例数据目录，再决定重试部署或按销毁流程处理。
- 任务消费者领取任务后拥有 5 分钟租约。服务崩溃导致租约过期时，控制循环会将任务重新排队；可在任务事件中查看 `lease_recovered`。
- 节点离线时，销毁与数据清理任务不会被伪造为成功。恢复节点和 Agent 后，待处理任务会自动重新投递；重点关注 `xcloud_nodes_offline_instances` 与 `xcloud_instances_destroy_blocked`。
- `purge` 只会在实例仍为 `destroyed`、保留期已结束且不存在有效订单时删除数据目录。物理清理完成后不可恢复，应在保留期内完成备份。
- 管理台“实例生命周期风险”与 Prometheus 规则共同用于告警。`XCloudRuntimeMissing` 需要人工核对后决定重试部署或销毁；`XCloudDestroyBlocked` 和 `XCloudOfflineLifecycleInstances` 只表示等待节点恢复，不允许跨节点迁移或伪造清理完成；`XCloudLeaseRecoveryRepeated` 需要检查消费者进程、RabbitMQ 连接和任务执行耗时。
- 隔离演练使用 `make integration-up && make test-integration && make integration-down`。至少演练部署失败、容器 404、消费者租约过期、节点离线后恢复、销毁与 purge；演练完成后确认测试 Compose 项目和卷已清理。生产回滚只允许回退应用版本或停用新入口，绝不可回退已执行的数据库迁移或恢复已 purge 的数据。

排障时保留任务 ID、实例 ID、节点 ID 和时间；不要复制令牌或 Cookie。
