# 运营平台升级部署说明

本版本增加钱包代币购买、多节点调度、站内通知和任务事件时间线。金额以整数分保存；100 分等于 1 代币，等于人民币 1 元。

## 发布顺序

1. 为控制面设置 `XCLOUD_NODE_TOKEN_ENCRYPTION_KEY`。使用 `openssl rand -base64 32` 生成，保存到控制面环境文件；不要写入前端、日志或节点读取接口。
2. 发布控制面。启动时会执行兼容迁移，创建用户目录、钱包、不可变账本、通知和任务事件表，并为旧默认节点加密现有 Agent 令牌。
3. 确认每台裸机 Agent 使用独立 `XCLOUD_AGENT_TOKEN`，防火墙只放行控制面和本机 Nginx 到 Agent 的 13092 端口。
4. 从超级管理台登记节点：填写 Agent 地址、独立令牌、CPU 和内存。保存前控制面会调用 `/container/status` 验证令牌；读取接口永不返回令牌或密文。
5. 安装 `deploy/nginx-instance-proxy.conf`。泛域名请求将先到控制面路由网关，再按实例路由键转发至对应节点。

## 运营规则

- 仅已登录过 xCloud 的用户拥有本地目录和钱包，管理员可为其新增正向或负向账本流水；不能编辑历史流水。
- 用户购买时在同一事务中锁定钱包、商品和健康节点，余额或容量不足不会扣款或创建实例。
- 调度在心跳 90 秒内的启用节点中选择 CPU/内存占用最大比例最低的节点。
- 任务失败进入有限重试，第三次失败记录死信事件。扣款不自动退款，管理员可通过负向账本流水冲正。
- 节点离线不参与后续购买；已有实例不会跨节点迁移。
- 管理员只维护可售镜像来源，例如 `registry.example/alemonx`。用户默认部署 `latest`，也可以选择同一来源下的其他 Tag；订单会保存实际选择的 Tag，用户不能提交未授权的镜像地址。
