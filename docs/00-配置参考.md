# 配置参考

配置按运行单元隔离；不要把所有变量写进根目录 `.env`。

| 运行单元 | 配置文件 | 负责内容 |
| --- | --- | --- |
| xCloud 控制面 | 根目录 `.env` | Auth、业务数据库、RabbitMQ、平台节点调度、自建节点 Gateway 调用 |
| 平台 `xcloud-agent` | `/etc/xcloud-agent.env` | 本机 Docker、实例目录、节点独立 Token |
| `xcloud-tunnel-gateway` | `/etc/xcloud-tunnel/gateway.env` | 设备长连接、Gateway Owner、Redis 目录、Gateway 间 mTLS |
| 自建 `xcloud-control` | `/etc/xcloud-control/config.json` | 一次性接入 Token、设备密钥、到公网 Gateway 的出站连接 |
| Nginx | 站点配置 | TLS、域名入口、控制面与 Gateway 反代；不保存业务密钥 |

## 控制面 `.env`

以根目录 [`.env.example`](../.env.example) 为唯一模板。生产至少填写 OIDC、MySQL、Redis、RabbitMQ、`XCLOUD_NODE_TOKEN_ENCRYPTION_KEY`、`XCLOUD_METRICS_TOKEN`、`XCLOUD_COUPON_CODE_SECRET`、实例域名和数据根目录。

自建节点相关变量只有四个：

| 变量 | 用途 | 谁能访问 |
| --- | --- | --- |
| `XCLOUD_TUNNEL_URL` | 用户服务器上 `xcloud-control` 连接的公共 WSS 地址 | 公网 |
| `XCLOUD_TUNNEL_INTERNAL_URL` | 控制面调用 Gateway 的 `/command`、`/terminal`、`/proxy` 地址 | 仅控制面网络 |
| `XCLOUD_TUNNEL_COMMAND_TOKEN` | 控制面访问 Gateway 私有接口的 Bearer Token | 控制面与 Gateway |
| `XCLOUD_INSTANCE_DOMAIN` | 平台与自建实例共用的 `xcloud-r<路由键>` 域名后缀 | DNS/TLS |

`XCLOUD_TUNNEL_URL` 与 `XCLOUD_TUNNEL_INTERNAL_URL` 可以指向同一组 Gateway，但必须是不同访问边界：前者只开放 `/connect`，后者只允许控制面网段。旧变量 `XCLOUD_TUNNEL_COMMAND_URL`、`XCLOUD_TUNNEL_PROXY_URL` 仅为升级兼容保留；新部署不得配置它们。

## 平台 Agent `/etc/xcloud-agent.env`

```dotenv
AGENT_ADDR=0.0.0.0:13092
XCLOUD_AGENT_TOKEN=节点独立随机令牌
XCLOUD_DOCKER_NETWORK=xcloud_network
XCLOUD_INSTANCE_DATA_ROOT=/var/lib/xcloud/instances
```

Agent 不读取控制面 `.env`。`13092` 只允许控制面 Docker 网段和本机访问。

## Gateway `/etc/xcloud-tunnel/gateway.env`

Gateway A 与 B 各自使用一个文件。两台必须共享 MySQL、Redis、`GATEWAY_COMMAND_TOKEN` 与 mTLS CA；`GATEWAY_ID`、`GATEWAY_INTERNAL_URL`、证书和私钥属于各自节点。

```dotenv
GATEWAY_ID=tunnel-a
GATEWAY_PUBLIC_LISTEN=:13072
GATEWAY_INTERNAL_LISTEN=:18443
GATEWAY_INTERNAL_URL=https://10.0.0.21:18443
GATEWAY_COMMAND_TOKEN=与XCLOUD_TUNNEL_COMMAND_TOKEN相同
MYSQL_DSN=...
SESSION_REDIS_URL=...
GATEWAY_TLS_CERT=/etc/xcloud-tunnel/tls.crt
GATEWAY_TLS_KEY=/etc/xcloud-tunnel/tls.key
GATEWAY_TLS_CA=/etc/xcloud-tunnel/ca.crt
```

`18443` 是 Gateway 间 mTLS 通道，不是控制面 HTTP API，也不应由 Nginx 暴露。

## 自建 Agent `/etc/xcloud-control/config.json`

```json
{
  "tunnelURL": "https://tunnel.alemonjs.com",
  "enrollToken": "一次性接入Token"
}
```

首次注册成功后客户端会写回设备 ID、凭证和 Ed25519 私钥。文件必须为 `0600`。不要填写数据库、平台 Agent Token 或用户 OIDC Cookie。

## 配置变更顺序

1. 修改对应运行单元的配置，不混改其他配置文件。
2. 校验格式和可达性：`nginx -t`、`systemctl status`、`/healthz`。
3. 先重启单个 Gateway 或单个 Agent，确认心跳/能力正常，再扩展至其他节点。
4. 令牌泄露时轮换令牌并重启相关单元；不要通过修改数据库或日志传递令牌。
